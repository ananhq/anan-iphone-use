# Anan iPhone Use

[English / Agent 入口](SKILL.md) · 简体中文

本文件是 `SKILL.md` 的中文说明；唯一 skill 名为 `anan-iphone-use`。

从用户的实际开发板出发，引导到 iPhone MCP 客户端连接完成。用用户的语言、小步骤和具体命令。StopWatch 复用现有实现，其他板型做经过确认的最小适配。固件执行 USB 输入；客户端负责观察、推理、规划和任务授权。

## 确认起点

- 仓库根目录是本文件的 `../../..`。先读 `AGENTS.md`、[路线图](../../../docs/roadmap.zh-CN.md)、[验证记录](../../../docs/validation.zh-CN.md)、[来源声明](../../../THIRD_PARTY.zh-CN.md)，检查 Git 状态，保留已有改动，不要求清空工作区，不覆盖另一 session 的工作。
- 只询问缺失的关键信息：准确板型/芯片/版本、电脑系统、USB-C iPhone 与选用的手机客户端、是否已烧录。区分负责安装的电脑 Agent 与真正操作 iPhone 的手机客户端。
- M5Stack StopWatch 走下方复用路径；其他板先读[适配指南](../../../docs/porting.zh-CN.md)，包括无屏分支。不能给其他板烧录 StopWatch 镜像，不能假设所有 ESP32 都有合适的原生 USB。
- 编译、静态和文档检查可直接进行。Agent 执行烧录、设备探测/动作、真实模型或 E2E，需要当前明确目标与范围的授权。仅触发 skill 不等于设备授权；当前已明确要求给该设备烧录，确认目标后即可执行，不重复询问。给用户命令自行运行不等于 Agent 执行设备动作。
- 不改 Anan 或其他客户端仓库，不擅自提交、发布、改远端、改目录名。保留 GPL 与上游声明，准确记录新增代码来源。

## StopWatch 复用与烧录

先读[配置与恢复](../../../docs/setup.zh-CN.md)，检查 `build.sh`、`flash.sh`、`package.py`、`sdkconfig.defaults`、`partitions.csv`。

1. 仅当已有镜像的 manifest 板型、镜像 SHA-256、当前源码 hash、依赖锁与构建设置均匹配时复用。编译标记不是设备验证。新 clone 当前没有已发布 Release 镜像；本地构建，除非确有可验证的发布版本。
2. 查找已安装的 ESP-IDF 环境。没有时引导安装官方 **v5.5.5** 与子模块，运行 `install.sh esp32s3`、加载 `export.sh`；Windows 使用官方对应操作。不写死维护者的临时 Python/IDF 路径，不悄悄换 SDK/依赖版本。在加载后的环境运行 `./build.sh`；Windows 用等价的 IDF 构建与 `python package.py build`。烧录前检查生成的 manifest 与 hash。
3. 让用户通过数据线把 StopWatch 原生 Type-C 接口连接电脑。按官方说明长按电源约两秒至绿灯亮，松开。根据当前系统枚举和插拔识别端口，不沿用历史端口。端口忙时查明占用者，关闭明确的串口监视器，不杀无关进程。
4. 使用实际端口与可用 Python 环境，给一条可直接运行的命令：通常 `./flash.sh <实际端口>`。已在下载模式但普通复位无法连接时，用配置文档中的 `--before no_reset` 命令。StopWatch 是 `esp32s3`、`16MB`，合并镜像 `build/anan-stopwatch-flash.bin` 写入 **0x0**，不能写到应用分区偏移。
5. 要求完整写入与 hash 验证成功；只有 Connecting 或 stub 启动不够。短按电源复位退出下载模式。失败先排查目标/端口/模式/镜像再重试。不默认整片擦除、恢复出厂、改 eFuse 或启用 Secure Boot。普通升级保留配对 NVS，重置/改分区可能清除。

## 烧录后：先连接手机并配置局域网

读[手机设置](../../../docs/setup.zh-CN.md)和 [MCP 配置](../../../docs/mcp.zh-CN.md)。已安装正确固件时从这里开始。已适配的其他板使用其确认过的实体操作；不能让无屏用户点屏幕。

1. **把数据线从电脑移到已解锁的 iPhone。** 通过确认的原生 USB 数据接口连接 iPhone ↔ 设备。在 iPhone 设置中打开新出现的 USB 以太网接口，手动 IPv4：**192.168.7.2**，掩码 **255.255.255.0**，路由器留空，不配 DNS。设备地址是 **192.168.7.1**。这是 USB 局域网，不是配置 Wi-Fi，也不提供互联网网关；保留手机 Wi-Fi/蜂窝网络供模型联网。没有以太网接口时先排查数据线、复位和 USB 枚举，再配对。
2. 打开「设置 → 辅助功能 → 触控 → 辅助触控」。保持竖屏、硬件键盘 US 布局。固件输入 ASCII，不支持中文/Unicode。
3. 根据当前可验证的官方发布途径，引导安装并打开**手机客户端**。没有已知途径就询问，不编造 App Store/TestFlight 链接，也不构建/修改客户端。允许本地网络访问。Anan 已支持 HTTP MCP；其他客户端需支持对应传输、Bearer 请求头与 JSON 导入/配置。核对真实界面/文档，不编造菜单名。
4. StopWatch 点「**设置 → 连接MCP应用**」。手机 Safari 打开 **http://192.168.7.1**，开始配对，核对六位验证码并在设备确认。配置窗口十分钟。HTTP **不用下载证书、安装描述文件或开启信任**；HTTPS 可选，不作为默认流程。
5. 确认后，同页自动生成 MCP JSON。让用户复制或下载 JSON，导入手机客户端，配置包含 **http://192.168.7.1/mcp** 与设备 Bearer 请求头。token/配置留在用户手机，不让用户粘贴到 Agent 聊天或提交入库。HTTP 剪贴板失效时手动选中复制或下载 JSON，不手写、猜测 token。
6. StopWatch 点「**已导入 返回 → 开始控制**」。其他板/无屏板使用另行实现的、全新实体操作来开启。客户端任务控制与屏幕共享单独开启；配对和 MCP 发现不等于设备输入授权。StopWatch 触屏、任一前置按键、`stop` 或拔线可停止；无屏用户必须得到该板明确的实体停止方法。
7. 获准连接检查时，只做 MCP 工具发现与 `device_status`，不发送 HID。六个设备工具：`device_status`、`tap`、`drag`、`key`、`type_ascii`、`stop`。观察由客户端提供，如 Anan 的 `phone.observe`，不是设备的第七个工具。Anan 系统屏幕共享当前需要 iOS 27+；核对实际客户端版本与系统。

## 收尾与排查

- 电脑/云端 Agent 不会因为支持 MCP 就能直接访问手机 USB 子网。导入手机本地 JSON 到电脑前解释可达限制。本 skill 与当前固件不提供网络桥接、Wi-Fi 或 BLE。
- 用户授权输入验证后，从观察、在空白测试备忘录做一个小动作、重新观察开始。HID/工具完成不等于 App 操作成功；验证获准的停止路径。不自动重放丢失/部分执行的输入，不重连即恢复控制。
- `USB origin/host required` 或超时：按当前源码/文档检查手机 USB IP/掩码、是否从手机访问、HTTP 地址、本地网络权限、导入请求头。不恢复旧 TCP28766，不放宽全部地址检查。StopWatch 黑屏用脱敏 `/status` 信息排查，不绕过显示授权。
- 汇报实际板型、必要源码改动、镜像 hash/版本、烧录结果、手机网络与 MCP 状态和用户下一步。分别说明编译、烧录、用户报告和设备验证；未执行的检查保持待验证。标识符、token、私人屏幕不进入仓库记录。
