# 基线验收步骤

[English](baseline-acceptance.md) · 简体中文

状态：仓库整理与编译/静态检查已完成，用户反馈重新烧录成功，随后明确授权先做首次
本地检查点提交。输入/停止检查和来源缺口仍待完成，该检查点不代表完整基线验收。
本步骤不授权助手烧录或操作设备。

## 确认候选镜像

使用 ESP-IDF v5.5.5 运行 `./build.sh`，核对
`build/anan-stopwatch-manifest.json`，并计算：

```sh
shasum -a 256 build/anan-stopwatch-flash.bin
```

候选目标必须是 M5Stack StopWatch / ESP32-S3 / 16MB，合并写入偏移为 `0x0`。
按[配置、烧录与恢复](setup.zh-CN.md)操作实际板子。记录镜像哈希与成功写入/哈希校验；
实际串口、设备 MAC 等标识和原始日志不进入可分享证据。

打包生成的 `flashed` 和 `deviceVerified` 初始为 false，因为打包不能证明设备执行。
重新构建会生成新的 manifest，不继承旧验收。手动结果按准确镜像哈希单独记录，
附日期及相关板型、系统和客户端版本。

## 建议的手动范围

使用解锁、竖屏的 iPhone、现有 Anan 客户端、USB-C 数据线、手动 USB IPv4 和
AssistiveTouch。在空白合成测试笔记中检查。每项可反馈通过、失败、未执行或结果未知。
以下是验收建议，不代表已经执行或接受这些场景。

| 检查 | 可观察结果 |
| --- | --- |
| 烧录与复位 | 写入/哈希校验成功，板子启动；黑屏符合预期 |
| USB 与连接 | 识别以太网和输入设备；Anan 连续保持连接至少 60 秒 |
| 预览与观察 | 完整竖屏可见；observe 返回真实画面且不产生输入 |
| 点击 | 单个选定目标被正确触发，没有重复输入 |
| ASCII/按键 | 短 ASCII 文字准确出现一次；单次 Return 有预期可见效果 |
| 拖动 | 单次滚动/拖动的方向和结果符合预期 |
| Anan 停止 | 中断有限输入，后续输入停止，记录已产生的局部效果 |
| 正面按钮 | 两个按钮分别在输入中测试，后续输入停止 |
| 拔线 | 输入中拔线；只显式重连，旧动作和排队动作不恢复 |
| 任务生命周期 | 任务结束后，新任务需重新授权；未知结果不自动重放 |

连续连接 60 秒是手动观察，不证明逐包 READY/PONG 覆盖，也不构成停止延迟测量。
保留可见局部效果；停止不会撤销已发生的输入。各项之间只显式重新启用。
不要在私人内容或有实际后果的 App 页面测试。

无 Mac 多步任务和长时间后台持续运行是独立检查，未做就保留未验证状态。
不能将基础输入通过写成完整任务/持续后台验收。手动运行是否使用真实模型由用户决定，
仓库整理不会发起真实模型调用。

## 反馈与提交

反馈日期、候选 SHA-256、相关版本、逐项结果，以及失败或未知效果。
简短文字反馈即可，不要求私人截图和原始日志。设备结果与来源问题分开：
烧录成功不能解决[来源缺口](../THIRD_PARTY.zh-CN.md)。

用户确认实际验收范围和来源处理后，补脱敏验证记录、同步更新两种语言的验证文档，
确认候选构建输入未改变，再形成已验收的本地基线 commit 并记录 ID。此前的本地检查点
由 Git 历史和[检查点记录](../artifacts/baseline/checkpoint.json)标识。
失败或未做项目明确保留；本地提交不授权 push 或公开发行。

本流程记录历史 ANAN1 检查点范围；当前 `0.4.0-mcp` 已退役该服务。
新候选采用[MCP配置](mcp.zh-CN.md)与当前[验证记录](validation.zh-CN.md)，
不再执行 READY/PONG 验收。
