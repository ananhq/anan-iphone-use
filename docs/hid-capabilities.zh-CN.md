# HID 能力扩展调研

[English](hid-capabilities.md) · 简体中文

后续实现：候选 `0.5.0-mcp` 已实现无需新增手机配置的功能子集，见[当前工具](hid-tools.zh-CN.md)。本文保留此前研究快照；真机行为仍未验证。

日期：2026-10-14。固件基线：`c794813f960b139089a1d4c72106e5c46c265b61`，`0.4.0-mcp`。

目标：提高手机端 [Anan](https://anan.sh) 操作 iPhone 的效率与准确性，优先通过固件扩展，保留现有客户端的 MCP 发现和图像观察。不修改客户端代码，不在本次运行手机、模型或硬件实验。

本文是源码与官方资料研究，不是已完成的功能列表。用户已认可键盘方向；实现仍未开始。候选接口、描述符与时序扩展应在实现前明确；既有报告、时序、物理授权、停止及不重放规则继续保留。

## 最值得优先利用的三部分

1. **现有鼠标报告没用满**：五个按钮、纵向 wheel、横向 pan 都已经在描述符里；动作层目前只用左键，滚轮值固定为零。
2. **Consumer Control 不只是媒体键**：Apple 官方表格还列出 Home、Spotlight、屏幕键盘与语言切换。需要新增报告，但可避免用视觉手势进入部分系统界面。
3. **更多完整、有界的手势**：长按、双击、先保持再拖动、多点轨迹可以由现有绝对鼠标执行，不必首先研究触摸屏模拟。

它们改善的是输入能力和执行粒度。ESP32 仍看不到界面、焦点、剪贴板内容或结果；是否更快、更准确要由同条件实验验证。

## 1. 滚轮：最小改动的实用方向

`main/usb.c` 使用 `TUD_HID_REPORT_DESC_ABSMOUSE`。锁定 TinyUSB `0.21.0~2` 的模板已有 5 个按钮、绝对 X/Y、相对纵向 wheel 和横向 AC Pan。`bridge_mouse()` 调用 `tud_hid_n_abs_mouse_report(..., 0, 0)`，最后两个零正是没有利用的滚轮值。[源码](../main/usb.c)

候选 `scroll` 可以先把指针放到列表区域，再发送少量纵向滚轮报告；不要把参数称为像素、行数或屏幕比例，因为实际位移由 iOS 设置、App 和控件决定。第一轮用很小的 signed delta 校准方向、幅度和自然滚动行为，之后再观察是否滚过头。横向支持另测，不从模板存在推断手机 App 一定响应。

适合设置列表、网页、长内容的小范围微调。它不保证比所有拖动更好：大范围翻页可能仍适合 drag，嵌套列表需要正确的指针位置。现有 USB 描述符可以不变，旧鼠标发送路径保留滚轮为零。

## 2. 长按、双击与拖放：补全手势粒度

目前 `execute()` 的 tap 是短按；drag 按下后立即沿两点直线移动，没有单独的拖前保持时长。[动作源码](../main/actions.c)

**一个无需改代码的小实验**：当前 `drag` 不要求起止点不同，传相同坐标会在指定时间内保持左键。例如下面是现有 `drag` 的候选实验参数，尚未真机验证：

```json
{"x":0.5,"y":0.5,"toX":0.5,"toY":0.5,"durationMs":700}
```

这只是“静止保持鼠标按下”，不能据此宣称每个 App 都识别成长按。当前 duration 仍限制 100…2000ms。

后续可提供命名 long press、double click 与 drag 的拖前保持。双击应在固件的一次有界动作中处理间隔，两次模型工具调用的时间不能等同于双击。拖放要区分按下等待、移动路径、释放，拖动速度和停顿也需要目标 App 试验。

每个动作都要在成功/中断时释放。第一批不开放跨多次 MCP 调用的永久按住状态，以免断线遗留拖动；完整动作继续复用现有 worker 和 grant 检查。

## 3. Consumer Control：系统入口与键盘管理

本次下载并检查 [Apple 官方 Accessory Design Guidelines](https://developer.apple.com/accessories/Accessory-Design-Guidelines.pdf)，版本 **2026-09-21**，第 14 章、表 14-3，印刷页 104–105。这里的 Apple Function 映射是官方文档依据，不是 StopWatch 真机结果。

| Consumer usage | 官方映射，可作为实验目标 |
| --- | --- |
| `0x0040` | Home |
| `0x0221` | Spotlight |
| `0x01AE` | 显示/隐藏屏幕键盘 |
| `0x029D` | Globe 键，语言/键盘相关操作依上下文 |
| `0x00E9` / `0x00EA` | 音量增/减 |
| `0x00CD` | 播放/暂停 |
| `0x00B5` / `0x00B6` | 下一曲/上一曲 |
| `0x006F` / `0x0070` | 亮度增/减 |
| `0x0030` | 锁屏；不是一个通用“解锁”命令 |

**这补充了此前 Fn 的限制**：当前 keyboard report 没有 Fn，但部分系统动作有独立 Consumer usage。不是把 Fn 塞进修饰位，而是发送另一个报告类型。

锁定 TinyUSB 已有 `TUD_HID_REPORT_DESC_CONSUMER` 和多数相关 usage 常量；本次未找到 `0x029D` 的命名枚举，该值来自 Apple 表格，可由模板表达，实际实现需明确记录常量来源。当前固件描述符只有鼠标 ID 1 和键盘 ID 2；候选方案是追加 Consumer ID 3，继续使用现有 HID 接口。Consumer 模板的 16 位 payload 加 ID 可放入现有 16 字节 IN endpoint，但枚举、组合设备兼容性、释放和 host 行为仍要验证。

首选 Home、Search、屏幕键盘与音量少量操作；亮度、Globe 和媒体上下文随后测试。不要把 usage 名称当作实际支持证明；也不要把音量增减写成“精确设置 30%”。显示键盘、播放暂停是状态切换，未知结果不可重放。不能把 HID 表里的通用 AC Back 假设成 iPhone 全局返回。

该指南还包含对配件真实控制输入和宏行为的要求；引用功能映射不代表本 Agent 自动化方案已获 Apple 认证或符合所有配件设计要求。

## 4. 额外按钮：利用系统已有映射

当前鼠标描述符声明 5 个按钮，`bridge_mouse()` 接收位掩码；动作实现只用 0/1。可扩展对按钮 2…5 的有界按下/释放，并让用户在 AssistiveTouch → Devices → 对应设备中选择该按钮的动作。[Apple 按钮分配说明](https://support.apple.com/en-us/111775)

Home、控制中心等系统入口可作为绑定实验目标；所选设备/系统版本是否提供该项，需以设置列表为准。不要把右键当作所有 App 的“返回”或“上下文菜单”；映射可能由用户更改。候选接口应明确发按钮编号，或仅在已确认的配置下提供语义名称。

优点是不一定改描述符；代价是首次设置和配置一致性。Consumer Home/Search 若直接可用，则不必为同一动作额外配置按钮；按钮更适合需要用户自定义的动作。快捷指令绑定是否可用应在目标系统独立核查，不在本文当作已确认能力。

## 5. 多点轨迹与指针预览

当前 drag 只有起止点，弧线需要多次调用且每段释放。候选 `draw_path` 在一次动作里按下，沿多点路径移动，结束释放，可以用于连续画狗、签名式笔画或框选。它仍是鼠标拖动，不是 Apple Pencil 压感、真多指输入或每个画布都支持的绘图 API。

小设计可限制 32 点、归一化坐标、总移动时间不超过 2000ms，同时满足当前 4096 字节请求和 8 秒动作上限；这些是讨论用界限。逐步检查 stop/cancel，不跨任务保持。改善的是连续性和少量调用，不是自动“理解一只狗该怎么画”。

`move_pointer` 则可以先移动不点击，观察落点后再点。要先确认系统共享截图是否包含指针，且别启用会因悬停自动触发的 Dwell。每次多一次观察可能更慢，不建议作为每个点击的默认前置。

## 6. 中文与文字编辑：HID 的边界

Cmd+A、Cmd+C/V、Cmd+Z 与方向/选择组合在协议层可以由当前普通键 + 修饰位表示；实际行为取决于 App 和输入焦点，命名键盘工具可帮助模型使用，实验只用合成文本。

复制/粘贴按键只是要求当前 App 操作剪贴板，USB HID 不因此获得读写任意 Unicode 剪贴板内容的通道。

Apple 明确说明外接键盘可使用文本替换：[官方快捷键说明](https://support.apple.com/en-kw/guide/iphone/iph3da414515/ios)。用户可预设 ASCII 缩写扩展为固定中文短语，作为小实验；它依赖手机设置、触发分隔符和输入上下文，Full Keyboard Access 的绑定也可能干扰。不能把固定短语扩展包装成任意中文输入。

通用中文仍可探索拼音 + 候选选择，或额外的手机快捷指令/剪贴板工作流；后者不是 HID 自己写入汉字，也不是只改固件就无配置可得的能力。当前不提出未经验证的完整 Unicode 输入接口。

## 7. 多指、触控板与手柄为什么暂缓

Apple 官方 AssistiveTouch 菜单提供多指、捏合/旋转及自定义手势，可先从菜单选择后用现有鼠标试验。系统生成手势与直接发送多个触点不是同一实现，且需要额外菜单/配置步骤。[Apple 手势说明](https://support.apple.com/en-us/111794)

HID Digitizer 规范存在，不等于任意 iPhone 接受一个新枚举的 USB 多点触摸屏。Apple 配件指南第 15 章的触控板功能明确从 iPadOS 14.5 开始；不能把它当作 iPhone 多指兼容性证明。

TinyUSB 有 Gamepad 模板，Apple 支持兼容的有线手柄；但通用模板是否被 iPhone/Game Controller 框架识别仍需测试。它更适合独立游戏演示，对当前日常 UI Agent 收益较小。[Apple 手柄发现说明](https://developer.apple.com/documentation/gamecontroller/discovering-game-controllers)

USB-IF 也明确指出 usage 的存在不意味着主机支持该 usage。[HID 规范入口](https://www.usb.org/hid)

## 实验顺序与共用检查

1. 已认可的键盘实验：可见焦点、搜索、输入；按[键盘文档](keyboard-navigation.zh-CN.md)执行。
2. 不改描述符的候选：纵向 wheel、静止长按、完整双击/拖放；对比当前 drag/tap。
3. Consumer report：逐项测试 Home、Search、键盘显示，再测试其他 usages；分别记录 USB 枚举成功和系统动作响应。
4. 有用户配置的额外按钮，以及连续轨迹；不同时修改多个影响定位的设置。

这是一组后续验收场景，本次未运行。每项先使用无害目标与合成内容，观察前后状态；记录操作耗时、工具/观察次数、误触和纠正。滚轮记录 signed delta 与实际位移，手势记录保持/间隔，Consumer 记录系统/App/媒体上下文。保持停止、拔线、取消后的释放和不重放；不能将 HID 传输完成当作任务完成。

新增能力继续由通用 MCP 工具提供；Anan 需刷新发现，仍使用现有图像观察。静态客户端检查支持这种集成方向，但新报告/工具的实际互操作、模型是否正确采用和净效率收益都没有验证。只有 keyboard 方向已被用户认可，本次研究没有顺带实施其他扩展。
