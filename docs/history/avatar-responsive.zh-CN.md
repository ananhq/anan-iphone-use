# 表情跟手与刷新修正

[English](avatar-responsive.md) · 简体中文

用户要求移除闲置气泡/灯泡，没有 MCP 输入时恢复普通眼睛与跟手体验，并同意已
讨论的显示/运动优化。本轮不烧录、不探测实机。

## 实现前定义的验收

- 任意闲置时间都不出现额外场景或强制向上看；保留本地触摸、表情浏览与倾斜。
  状态查询不增加动画。
- MCP 指针/滚动目光只作为体感上的小幅附加偏移，不模拟触摸来覆盖倾斜。
  真实手指触摸保留直接目光。
- 将上游每帧截断至 33ms 的欧拉弹簧替换为使用真实耗时的解析临界阻尼运动，
  目标有界。恒定目标下一步 200ms 应与五步 40ms 一致，长停顿后仍有限稳定；
  眼睛比头部快。减少首方重力校正延迟，不改 IMU 地址、总线、量程、速率或停止。
- 短输入道具保持约 480ms，再用 140ms 淡出，并保留短执行结束尾段。新道具
  立即替换旧道具，不双画面叠加；执行中持续显示，不增加输入重放或等待。
- 只栅格化实际紧凑矩形并直接使用其步长；复用现有内部 DMA 缓冲，窄区域一次
  传输更多行。合并重叠变化区、跳过图元语义不变的分组，去掉裁剪时反复整宽
  重绘/压缩搬移。
- 预定义场景覆盖 20 秒闲置无道具、MCP 时体感仍有效、真实时间弹簧、各输入
  类型局部/整帧等价、切换/退出/时钟回绕、相同帧不传输，以及假 SDK 下实际
  紧凑 DMA 的步长/容量/重叠/错误/超时。复用停止/授权、HID/无线/IMU、源码
  提供和模拟烧录检查。
- 只为表情热路径启用 `-O2`，不启用 fast-math、不全局改变输入优化或增加依赖。
  核对目标栈与静态 RAM 增量；五秒诊断在现有帧率/绘制耗时基础上增加真实 DMA
  次数/像素数，不记录坐标或私人输入。
- 保留上游来源和许可，明确记录交互修改；双语文档同步，单独编译打包候选并
  核对嵌入源码包，生成原生合成预览。

实际帧率/延迟、传感器噪声、共存、撕裂或持续残影及停止延迟另待设备验收。
离线栅格等价不能证明屏幕扫描同步或实机性能。

## 细残影修正：运行时代码修改前定义验收

用户反馈 0.9.2 已流畅，但有很细的残影。现有整帧/局部栅格检查通过，却没有
约束实际屏幕刷新窗口：80px 宽区域会分成 93 行一块，即使初始 Y 为偶数，
下一块也会落在奇数行；原生边界也允许奇数 Y/高度。固定版本的 Espressif
驱动直接传递这些地址。独立查阅的
[Zephyr CO5300 驱动](https://github.com/zephyrproject-rtos/zephyr/blob/2afc59f6d9784ad7013242d5477cba9745dde484/drivers/display/display_co5300.c#L125)
明确将起点和尺寸对齐到偶数。这是明确的对齐缺口；尚不能据此证明实机残影原因。

- 将紧凑变化区起点向下、排他终点向上对齐到偶数，限制在 466×466 屏幕内。
  扩展像素使用当前场景完整重绘，包含黑背景；扩展后再合并重叠区域。
- 每个 DMA 分块都保持偶数起点和尺寸；可容纳行数向下取偶数，沿用现有缓冲
  与完成等待。保留紧凑绘制、不变帧跳过和当前运动表现。
- 实现前扩展既有假屏幕场景：拒绝任意奇数窗口；检查奇数起点、1px 尺寸/移动、
  四周边缘、整屏和不同窄区域分块容量的逐像素覆盖，无遗漏或重复。
  复用表情局部/整帧、普通 UI/停止/输入检查；不增加延迟、周期性整屏刷新、
  硬件初始化或依赖变更。
- 单独编译打包 `0.9.3-avatar-edges`，核对嵌入源码包；本轮未授权设备操作。
  持续残影与扫描撕裂仍待实机验收。
