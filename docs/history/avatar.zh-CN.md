## 设计与来源

参考 [Trentct/m5stack-stopwatch-avatar](https://github.com/Trentct/m5stack-stopwatch-avatar/tree/204963257cb4dc2f3d7501eff900897bac55ef82)，
固定提交 `204963257cb4dc2f3d7501eff900897bac55ef82`，AGPL-3.0-or-later。借鉴其
姿态/表情/交互分层、眼快脸慢、连续衔接与变化区域刷新思路，不引入其表情代码、
数据表或美术素材。沿用原生 ESP-IDF，不引入 Arduino/M5Unified/M5GFX，不改
项目许可证；参考项目公布的帧率是其测量，不能套用到本固件。

StopWatch C152 的 BMI270 位于 I2C 0x68，SDA47/SCL48，已核对
[官方规格](https://docs.m5stack.com/en/core/StopWatch)。固定工厂示例
`6b4aa125288b6fe9dca661f10159f6e1e5ee785c` 的 `main/hal/hal_imu.cpp` 将原始 X/Y
交换到屏幕坐标。Bosch SensorAPI 固定提交
`41129fcfe39c583ee5462d79195741945d51c1fe`，基础 BMI270 v2.86.1：原样引入
`bmi2.c/h`、`bmi2_defs.h`、`bmi270.c/h`，含传感器配置数组，BSD-3-Clause；准确
哈希和声明见 THIRD_PARTY。

- 有界的低优先级 IMU 任务初始化并采样；纯重力/陀螺仪滤波输出有界屏幕相对
  倾斜，不宣称指南针航向。进入时自动建立中性位置，无校准页面；无效/过期数据
  平滑回中，IMU 失败不阻断 MCP。
- 复用动作线程通知，显示线程独占的动画状态以阻尼运动接近目标，中断也从当前
  姿态接续。眼睛快、整张脸慢；输入执行不等待绘制，实体停止仍独立于 I2C/显示。
- MCP 表情优先于触摸反应，执行时只叠加轻微倾斜。控制画面触碰/拖动只改变
  视线和短暂表情，不向手机发送输入、不进设置、不授权/撤销控制；读取错误仍
  保留既有保护性停止。
- 首次进入/退出眼睛页整屏刷新，后续重画新旧双眼包围区域的并集并清除旧像素，
  复用 DMA 分条缓冲。标称目标 30fps，调度扣除绘制时间；实际速度、观感、功耗
  仍需测量。

## 运行时代码修改前定义的验收

- 纯函数场景：倾斜有限/有界、屏幕轴映射、静止漂移、失重/运动排除、时间回绕
  与过期恢复；眼睛位于圆屏内、圆角/眼睑、触摸反馈、MCP 优先、表情可辨、
  中断/松手连续过渡和重置。
- 假显示运行实际裁剪传输：字节序/步幅、边界、末尾短条、区域外不发送、错误
  传播和不复用完成状态未知的 DMA 缓冲。连续局部帧合成后须等于完整帧，无残影。
- 假 I2C/SDK 运行实际 IMU 适配，覆盖缺失、初始化/读取错误、有界回调及驱动哈希。
- 修改前扩展实际控制/触摸场景，允许本地视觉通知且授权/停止/页面不变；复用
  动作时序、实体停止、纯黑 UI、目标栈预算和 HID/无线/模拟烧录检查。
- 固定 SDK 编译打包、原生静态/GIF 预览；不在实现后新增单测。另行授权的真机
  验收：方向/中性位、保持角度、触摸/拖动/松开、各类输入、快速切换、停止/断连、
  设置导航、无残影、实际帧率及功耗。

本范围不隐含烧录、串口/无线探测、手机/客户端/provider 或 E2E 执行。传感器方向、
触摸手感和与输入共存均须设备验收。
