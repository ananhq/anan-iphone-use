# BLE 单绝对鼠标对照

[English](ble-absolute.md) · 简体中文

## 实施前约定的对照与验收

用户反馈 `0.7.4-ble-drag` 在 BLE 下仍只有第一笔能画上，而 USB 可用，并同意先
验证 BLE 使用 USB 报告结构，再考虑相对移动校准。候选 `0.7.5-ble-absolute`
移除额外的相对鼠标 Collection/报告 ID4，保留绝对鼠标 ID1、键盘 ID2、Consumer
ID3 及键盘 LED 输出 ID2。BLE 报告映射应与现有 USB 完全一致。

坐标、按钮和滚轮统一使用绝对报告 ID1；就绪只要求绝对鼠标及键盘订阅，Consumer
订阅仍可选。每次移动/滚轮发送一份通知，在最后报告的坐标释放。保留 USB、执行器
等待、MCP 工具/schema、安全配置、存储、供电、授权及不重放行为。不修改客户端，
不引入依赖、校准或相对运动实现。

修改运行代码前，重新定义发送 fixture：要求与 USB 一致的描述符列表、三个输入
引用及键盘输出引用、不依赖 ID4 的就绪条件、合并的坐标/按钮/滚轮载荷、三条独立
笔画、按住后释放、通知失败不重放及离线/断连行为。执行既有 HID/无线/烧录检查、
锁定 SDK 编译/打包及源码/manifest 核验，实施后不新增测试。保留上一候选镜像及源码。

本次会改变 BLE 报告映射及 GATT 表。后续另行授权的真机验收，需要手机忘记
Anan StopWatch，设备重置蓝牙后重新配对，排除旧缓存/绑定。这仅针对本候选切换，
普通辅助脚本升级仍保留 NVS，MCP/Wi-Fi 配置保留。先测普通 tap，再在空白备忘录
绘图区画三条固定独立笔画，并核验滚轮、键盘和停止。若点击失效，不应认定候选
可用或让模型补偿；应恢复前一候选并重新配对。本源码/构建范围未授权烧录或手机操作。

BLE 是否接受绝对鼠标按钮是本次实验，尚不是已确认事实。USB 字节相同不证明
iOS 行为相同；备选的相对混合拖动仍需另行讨论校准设计。

## 候选结果

预定义电脑端场景及既有 HID/无线/保留绑定烧录检查通过。此前双鼠标实现未通过
预定义的 USB 映射相等断言。固定 ESP-IDF v5.5.5 编译/打包完成，编译警告为零。
从编译后 ELF 提取的两份映射均为 172 字节且完全相同；这只证明描述符一致，不
证明手机验收。源码核验确认 USB、执行器时序、七工具、安全/存储及依赖保留，
见[脱敏记录](../../artifacts/wireless/ble-absolute-build-check.json)。

候选镜像：`build/ble-absolute-candidate/anan-stopwatch-flash.bin`。上一候选的镜像及
匹配源码快照保留在忽略的 `build/ble-drag-candidate/` 中。使用当前保留 NVS 的烧录
辅助脚本，但因为报告映射改变，按上文明确重置 BLE 并重新配对。无需重置 MCP/
Wi-Fi 配置。本轮未实际烧录或测试 iPhone。
