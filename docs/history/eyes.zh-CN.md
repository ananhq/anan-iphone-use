# 控制眼睛动画

[English](eyes.md) · 简体中文

当前倾斜/触摸与平滑绘制替换下文的被动表情，见[可交互表情](avatar.zh-CN.md)。

`0.7.8-eyes` 实现前约定的范围与验收：

- 新点击“开始控制”授权后，首页替换为纯黑背景和两只浅色实心眼睛，不保留
  文字、电量、状态、按钮或触摸目标。任一正面实体键停止并返回普通首页，按键
  消费至完全松开。控制中忽略所有触碰；读取错误仍撤销授权。MCP stop、输入/
  显示断开和重启仍撤销控制。
- 空闲眨眼；点击/长按/双击压眼，拖动/连续路径跟随最近成功发送的指针坐标，
  打字轻跳，滚动沿方向看，键盘/Consumer 按键眨单眼。若控制仍启用，输入失败
  短暂显示低落表情。这些是输入反馈，不表示手机任务成功或模型思考。
  状态查询和工具发现不触发动作动画。
- 工作线程开始/结束和指针通知只发布有界原子视觉元数据，不保存文本/按键内容，
  不绘制、不分配、不等待、不增加 HID 报告。原有低优先级显示任务按标称 40ms
  间隔采样形状。原版短动作至少显示 400ms；新动作覆盖旧动画；新授权清空旧表情。
- 保留 MCP 工具/参数、HID 描述符/发送/执行等待、实体停止和供电策略，不改客户端，
  不增加依赖或外部素材。电量仅在停止状态的普通首页轮询。
- 运行时代码修改前，定义主机检查：控制页无组件/触摸目标、忽略所有触碰、两个
  实体键及松开消费、形状边界、坐标跟踪、重置/覆盖/停留/时间回绕、纯黑背景。
  复用 HID/无线/烧录离线检查并编译打包；预览复用原生采样与分条绘制。
- 实际帧率、观感、共享总线响应、实体停止延迟、动画负载下 BLE/USB 输入需另行
  授权的设备/手机验收，主机检查和编译不证明这些结果。

本次替换 `0.7.7` 的控制中停止按钮；配对和设置布局保留。修改本身不授权烧录、
设备探测、手机/客户端或 E2E 操作。

## UI 栈空间修正：实现前定义

`0.7.8` 后用户反馈：首页点设置绿闪且无响应。未采集设备日志/复位原因。
目标编译器确认布局命中辅助函数各占 2592 字节栈，而触摸/按键线程仅分配
4096 字节。触摸路径叠加线程、布局及所链接 libc 格式化函数栈帧已超过预算，
还不含所有更深调用/运行开销。这是源码/构建确认的资源缺陷，尚非真机确认的根因。

`0.7.9-ui-stack` 将两个交互 UI 线程各改为 8192 字节，任务栈合计增加 8 KiB。
显示供电/时序、布局、眼睛、触摸命中、输入报告、动作执行和停止函数体保留。
运行时代码修改前定义 `tools/check_ui_stack.py`：以候选的实际目标参数重新编译
UI 源码并生成栈用量，读取链接 libc 的入口栈帧；每个 UI 线程须容纳已知格式化
调用链及额外 2 KiB 余量。先验证旧分配失败，再验证修正。复用 UI/HID/无线/烧录
离线检查及固定 SDK 编译打包。静态余量不代表完整最坏情况证明或实测栈高水位。
另行授权的实机验收：首页设置→各子菜单→返回、短按/长按、开始→眼睛→任一
实体键退出，无重启/绿闪，输入和停止行为保持。

## 加强动作反馈：实现前定义

用户反馈栈修正后导航正常，但动作反馈看起来仅为空闲眨眼。源码追踪确认工作线程
开始/结束和成功发送指针的通知已连接。原键盘眨眼/点击峰值仅约 200ms，打字最多
移动 8px，指针视线最多 30px。未采集实机通知或显示帧时间。

`0.7.10-eyes-feedback` 从第一帧即给出明显表情，加大坐标视线和交替打字跳动，
滚轮大小仅映射为有界方向，不作为无限位移。
短动作从开始保留 900ms，且结束后至少保留 320ms，再用 240ms 回落；新输入
立即覆盖。键盘持续保持单眼差异，点击/长按在脉冲之间也保持眯眼。不改变绘制
频率、纯黑无字 UI、输入报告/等待、停止或客户端/MCP 行为。

运行时代码修改前扩展主机验收：每类输入第一帧即可辨认；即便动作仅 20ms，
在带相位偏移的合成 160ms 帧间隔下也有至少四个明显样本，之后回到空闲。
以合成时间/报告运行实际队列工作函数，验证开始/结束通知及点击/打字/按键时长
不变。复用形状/绘制/停止/栈检查及固定 SDK 编译打包。这些检查不测量实机帧率，
也不证明设备观感。另行授权的设备验收：点击、长拖动/路径、ASCII 输入、滚动、
Home/搜索按键有可辨认反应，实体停止仍即时生效。
