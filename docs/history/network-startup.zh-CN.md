# 网络启动诊断

[English](network-startup.md) · 简体中文

## 离线重启证据：运行时代码修改前定义验收

用户反馈回退后，点击配置 Wi-Fi 短暂黑屏再回首页，USB `/status` 也不可达。
这提示可能重启，尚未证明。准备 `0.9.8-reset-info`，不宣称修复网络：

- 恢复与 0.9.6 逐字节相同的 sdkconfig 默认配置；不启用 PSRAM、不新增无线分配
  或输入改动。关闭 PSRAM 时编译排除相关状态 API。
- 小型带校验和的 RTC no-init 记录只保存 AP 阶段/错误、内部当前空闲/最大连续块
  及调用任务的栈高水位剩余字节数。在既有 AP 进度点及错误回退前记录；仅软件/
  panic/看门狗重启后读取有效的上一条，上电、掉电、无效/不完整记录则丢弃。
  不写 NVS、不存日志或凭据。
- 既有连接与配网页显示重启原因/运行时长、内部当前/最低/最大连续块及上次 AP
  记录。保留全部按钮位置、配对/输入授权、停止行为及正常控制动画。
- 修改前预定义合成保留/校验/重启类别场景，扩展实际设备/布局/启动检查；检查
  PSRAM 状态的两个编译分支、双语、基线 SDK 配置及目标栈预算。
- 实机验收另行进行：手动尝试一次配网前后比较重启原因/运行时长，若重启则读取
  上次阶段/堆/栈。保留的阶段仅是最后记录事件，不证明该 SDK 调用导致崩溃。
  本轮不执行烧录、新增实机探测或手机操作。

## 压缩缓存修正：运行时代码修改前定义验收

用户的 0.9.8 图片显示 AP MODE 报 0x101，内部空闲 6,388 字节、最低约 1.1KiB、
最大连续块约 4KiB、重启原因 1 为上电。该次确认分配失败，没有确认 panic。
目标符号显示：两份表情命令缓存各 6,400 字节，边界缓存 2,560 字节，分组 160 字节。

- 保留 160 容量、全部图元/颜色/变换。当前及上一帧命令改存 16 字节的类型/颜色/
  六坐标记录，裁剪后的边界改存八字节；绘制时解码后沿用整数运算，保留有意义
  字段及直线变换后的备用坐标。
- 压缩前检查有符号坐标范围，超出时沿用溢出拒绝。目标释放 8,960 字节静态内部
  内存，不启用 PSRAM、不改任务栈、不删动画、不改无线配置或 MCP 协议。
- 修改前保存原生参考程序，预定义闲置、全部输入家族、体感、触摸、动作替换及
  长混合场景的整帧 RGB 对比；运行既有整帧/脏区、命令上限、DMA、时序、输入/
  停止和无线检查，核对目标栈与链接映射。
- 打包 `0.9.9-compact-cache`，保留重启证据和对应源码。不烧录/新增实机探测。
  实际余量、热点/扫描/HTTP/MCP 与动画外观仍需实机验收；增加容量不能证明全部
  网络故障或可能的泄漏已经修复。

**0.9.7 实机反馈：未通过验收。** PSRAM 候选交付后，用户反馈首页出现、按钮无
响应，随后黑屏。这是启动回归报告；烧录哈希、是否崩溃/重启及根因尚未独立确认。
停止推荐 0.9.7；保留的 0.9.6 镜像用于恢复之前可操作的界面，不代表修复其已知
低内存网络故障。用户随后反馈已回刷；Agent 没有执行设备恢复。

用户反馈已配置的 USB 与普通 Wi-Fi 均无法访问 HTTP，点击配置 Wi-Fi 后没有二维码
或热点。已授权的只读局域网检查得到 HTTP80/HTTPS8443 超时及邻居地址未解析；
这不能确定固件根因，也不能排除局域网隔离或主机限制。本轮不改变客户端、无线
工作模式、配对存储或输入协议。

## 运行时代码修改前定义的验收

- 记住用户进入的是 Wi-Fi 配置。热点就绪前显示实际启动阶段/错误，不再显示无关
  的连接 MCP 应用引导；保留普通 MCP 配置、实体配对、二维码、返回/停止及热点期限。
- 记录排队、释放输入、暂停 BLE、模式、配置、启动、就绪阶段及实际 API 错误。
  请求被拒或驱动失败时屏幕可见，保留失败阶段及设置，仅沿用既有回退。
  API 成功不代表手机实际收到广播或网络已通。
- 将 HTTP 启动成功/错误与原有 HTTP 或 HTTPS 任一可用的控制就绪状态分开。
  配网等待/失败页显示 HTTP 及当前/最低空闲堆，连接与配网页增加简短 HTTP 状态。
  保留授权规则，仅向既有只读 `/status` 添加无秘密诊断字段，不增加 MCP 工具。
- 预定义假 SDK 场景覆盖请求拒绝、异步排队、各 AP API 失败/成功/回退，以及
  HTTPS 就绪但 HTTP 启动或路由注册失败。扩展既有设备/布局场景，覆盖延迟
  热点启动、正确配置上下文、双语、返回及原有停止。
- 单独编译打包 `0.9.4-network-diagnostics`，核对源码、目标栈并生成原生 UI 预览。
  保留 0.9.3 回退。本实现阶段不烧录、不发送 HID、不改变设备配置、不新增实机探测。

本候选用于诊断，尚不宣称修复未确认的网络根因。另行授权烧录后，需要屏幕阶段、
错误码、空闲堆及实际 USB/Wi-Fi/热点表现完成实机判断。

## 工具发现后续：运行时代码修改前定义验收

用户重置 MCP/重启后恢复地址访问，随后初始化成功但工具发现报 URLError -1005，
之后变成 HTTP503。源码确认：四个会话闲置十分钟才过期，客户端固定版本 SDK
断开时不发送 DELETE；`/mcp` 初始化还把随机数失败混用为会话已满提示。这能
解释可能的名额耗尽，尚不能解释最初断线。后续只读状态读取收到 HTTP200 基本
响应头，但六秒内正文未传完；网络/传输故障根因仍未确认。

修改前主机测量：4,825 字节目录的固定 cJSON 解析树占 18,853 字节，序列化峰值
29,721 字节，22,290 字节预算下序列化失败。自定义分配钩子会关闭 cJSON 的
realloc 快路径；这些是主机分配量，不是板端内存不足的证明。

- 用既有静态目录和编码后的请求 ID 直接组装相同 JSON-RPC tools/list 响应。
  保留 Content-Length、状态/类型、工具定义、认证、会话、防重放记录和时序。
- 预定义数值、引号/控制字符/UTF-8 ID 的逐字节等价，以及分配/发送失败和释放
  场景。新响应应能在增量 8KiB 的合成堆预算内完成，并与旧实际路径比较。
- 区分会话已满和随机数失败的错误文字；只读 `/status` 用非阻塞锁报告无秘密
  会话占用量及既有堆信息。不改 TTL、不驱逐会话、不修改客户端或输入执行。
- 将前一版诊断一并打包为 `0.9.5-tools-memory`；构建和静态检查不能证明减少
  堆使用已解决实机故障。

## 热点重新进入后续：运行时代码修改前定义验收

用户反馈重启后完全无法访问，配置 Wi-Fi 又回到首页。实际烧录版本及是否发生硬件
重启尚未确认。源码发现两处生命周期竞态：热点仍开启时的新请求直接返回，没有
撤销待执行的关闭；屏幕检测旧热点关闭后，会无条件退出两帧之间刚打开的新配置页。

- 预定义实际函数场景：热点待关闭时重新进入、旧热点关闭后新请求排队、重启热点
  失败，都应保留新的配网意图和可见诊断；真正过期仍应退出。
- 每次显式配网请求都重新置位意图，即使热点尚未关闭；只在没有新请求且没有配网
  错误时自动退出旧热点关闭页面。保留 AP 模式/期限、用户返回、停止和配对要求。
- 诊断配网页显示构建版本、数字重启原因及运行时长，区分页面返回与真实重启；
  只读状态页增加重启原因/运行时长。不改日志传输、供电或无线模式。
- 单独构建 `0.9.6-hotspot-lifecycle`。这修正离线复现的导航/请求竞态，尚不代表
  已解决全部网络故障；启动和重启原因仍待实机验收。

## PSRAM 后续：运行时代码修改前定义验收

用户提供 0.9.6 屏幕：AP MODE 阶段报 0x101（`ESP_ERR_NO_MEM`），当前空闲
2,396 字节，最低 1,084 字节。这确认热点模式切换时分配失败，但不能确定申请
大小、是否泄漏或之前所有网络故障的原因；重启原因 1 表示上电。讨论限制和保留
现有功能后，用户同意尝试 PSRAM。

- 沿用固定版本 M5Stack 出厂配置：Octal PSRAM、80MHz、启动初始化及内存自检。
  SDK malloc 使用 1KiB 内部优先阈值及 32KiB 内部/DMA 预留。任务栈、NimBLE、
  TLS 分配模式及 LCD DMA 缓冲保留内部；不迁移可执行代码、静态 BSS、表情缓存
  或中断数据。
- SDK 支持的 Wi-Fi/lwIP 分配优先 PSRAM。显式保留十个静态 RX 缓冲，采用 SDK
  兼容 PSRAM 的十六个静态 TX 缓冲及有界缓存队列，避免默认值暗中变化。
  保留六帧接收 BA 窗口及每个 TCP 连接四个乱序 pbuf 的原有限制。
  内部 TX 缓冲约占 25.6KB；PSRAM 容量不等于内部空闲容量，余量必须实机确认。
- 实现前扩展合成设备/布局场景：区分内部当前/最低空闲、最大连续块和外部余量；
  新增实际诊断函数的 PSRAM 正常/不可用场景，保留原总堆字段。核对最终 SDK
  配置、任务/USB/BLE/屏幕/输入行为保留、源码归档和打包。
- 单独打包 `0.9.7-psram-memory`，保留 0.9.6 回退。本轮不执行烧录或新增实机
  探测。实机验收：确认 PSRAM 初始化与容量；保留配对/Wi-Fi 冷启动；反复进出
  热点配置并扫描；检查 USB 和 Wi-Fi HTTP/status、初始化和工具发现；随后另行
  授权验证 BLE/USB 输入与实体停止。记录重复操作中的内部当前/最低空闲及最大
  连续块，区分瞬时需求、碎片和可能的泄漏。构建/静态检查不代表已恢复多少容量、
  长期稳定或手机操作成功。
