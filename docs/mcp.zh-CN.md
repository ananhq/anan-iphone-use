# 设备端 MCP

[English](mcp.md) · 简体中文

当前是已实现的开发版；编译/静态证据与手机、TLS、显示和互通验收分开。
MCP 是当前唯一控制协议；[PROTOCOL.md](../PROTOCOL.md)保持为历史 ANAN1 契约，28766端口已移除，本文描述当前 MCP。
固件不运行 Agent、不采屏；没有修改 [Anan](https://anan.sh)。

Anan iPhone Use（`anan-iphone-use`）提供设备端 USB 输入执行；客户端的屏幕观察、推理、规划和用户授权仍分开，见[客户端 iPhone Use 描述](client.zh-CN.md)。本端点没有 `observe` 工具。用户反馈对 MCP 满意，与带版本的互通/停止验收证据分开记录。现已实现 HTTP80 `/mcp`，同时保留可选 HTTPS8443。用户反馈 Anan 已支持 HTTP，本固件仓库不修改该客户端。

## 首次配置：HTTP，无需安装证书

1. 用数据线连接解锁的 iPhone 与 M5Stack StopWatch。USB 以太网配置为 `192.168.7.2/24`，无网关/DNS，并开启辅助触控，见[配置说明](setup.zh-CN.md)。
2. StopWatch 点“设置 → 连接MCP应用”；中英文语言选择会记住。
3. Safari 打开 `http://192.168.7.1`，点“开始配对”，核对六位数字，在 StopWatch 点“确认配对”。配置窗口十分钟后过期。
4. 确认后，同一网页自动生成 MCP JSON；复制或下载后导入 Anan 或兼容 HTTP MCP 的客户端。导出端点为 `http://192.168.7.1/mcp`，带设备独立 Bearer 请求头。无需安装描述文件或开启系统证书信任。
5. StopWatch 点“已导入 返回”，再点“开始控制”。控制持续至停止/拔线/重启或其他已记录撤销事件。发现工具/读取状态不授权输入；控制时触屏或按任一正面实体键停止，同次接触不会再启用。

明文 HTTP 不提供 TLS 加密，仍限定原有准确 USB 地址/Host/Origin。HTTPS 保留在网页折叠的可选区域：HTTPS 配置页导出 `https://192.168.7.1:8443/mcp`，仍需原有证书安装/信任。两种传输共用六个工具、会话和 HID 执行器；HTTP 控制不再依赖 HTTPS 启动成功。

网页只在标签页 session storage 保留临时配对凭据；配置/token 留在页面/下载中，不放入 local storage。HTTP 下安全上下文剪贴板 API 不可用时使用浏览器复制备用方式，仍可选中文本复制或下载 JSON。实际 Safari 复制行为待真机检查。关闭、过期或重新配对后，重进“连接MCP应用”再开始。配置导出要求物理确认、有效十分钟窗口及临时 HttpOnly、SameSite Strict 设置 Cookie。重新物理配对可导出现有 token。

## 从旧 HTTPS 配置重走新用户流程

1. 烧录有明确标识的 HTTP 候选镜像，正常复位；不整片擦除 Flash。
2. iPhone 打开“设置 → 通用 → VPN与设备管理”，仅选择 **StopWatch Local CA**，点“移除描述文件”，按要求输入手机密码，不移除无关描述文件。见 [Apple 描述文件说明](https://support.apple.com/guide/iphone/install-or-remove-configuration-profiles-iph6c493b19/ios)。
3. 在客户端 MCP 设置中删除旧 StopWatch HTTPS 连接，关闭旧配置网页标签；下载过的描述文件/旧 JSON 可另行删除。
4. StopWatch 点“设置 → 重置配对”，按住红色确认按钮两秒。清除身份/CA/token 并停止控制，保留语言偏好；不重置 iPhone 所有网络设置。
5. 按上方 HTTP 首次配置重新操作，确认导入 JSON 使用 `http://192.168.7.1/mcp`，不是 HTTPS8443。客户端连接/状态检查与真实手机输入验证分开记录。

身份仍在板上生成，保存在 `0xf00000` 的独立 `mcp_kv` NVS 分区，正常合并镜像不含身份数据，普通升级保留。整片擦除、工厂恢复或不同分区布局可能移除它。重置只清除身份命名空间，不清除语言；命令/动作/授权不持久化。

原 ECC P-256 CA/服务端证书生成及续签路径保留，用于可选 HTTPS 和兼容；HTTP 不要求手机安装或信任此 CA。不增加 Wi-Fi、云、OAuth、mDNS 或共用签名私钥。身份仍为普通 NVS 存储，本阶段不加入 Flash 加密/Secure Boot。

## 地址和工具

`http://192.168.7.1/mcp` 与可选 `https://192.168.7.1:8443/mcp` 实现 MCP **2025-11-25** Streamable HTTP：
POST 返回 JSON，已认证 GET 返回 405，DELETE 终止会话，通知返回空 202。
没有 SSE 重放、任务扩展、资源、提示词、sampling、截图或自动输入重试。
当前只供连接数据线的手机访问；电脑/云 MCP 客户端需要其他网络通路，不在本阶段范围内。

| 工具 | 必填参数 | 含义 |
| --- | --- | --- |
| `device_status` | 无 | USB 在线、模式、输入忙碌、权限及剩余时间 |
| `tap` | `x`、`y`：0…1 数值 | 竖屏归一化绝对坐标点击 |
| `drag` | `x`、`y`、`toX`、`toY`：0…1；`durationMs`：100…2000 整数 | 有界拖动 |
| `key` | `keycode`：4…231 整数；`modifiers`：0…255 整数 | 一次 USB HID 按下/松开 |
| `type_ascii` | `text`：1…120 字节，US 布局可打印 ASCII 加 TAB/LF | 有界键盘输入，不支持 Unicode/输入法 |
| `stop` | 无 | 撤销 MCP 权限，中断共用 HID 并请求释放 |

未知参数会被拒绝。完成仅代表 HID 序列完成，不代表 App/任务成功。失败、取消或响应
丢失可能已经产生部分效果，应另行观察手机，不自动重试。`phone.observe` 是 Anan
原生工具，不是板上的 MCP 工具；其客户端屏幕共享/归属要求与设备 MCP 输入分开。

## 会话和停止边界

不带会话头发送 `initialize`，接受协商版本，保留 `MCP-Session-Id`，再发送
`notifications/initialized`。后续 POST 带会话头和
`MCP-Protocol-Version: 2025-11-25`。每次 MCP 请求都要求设备独立生成的 256 位
Bearer；会话 ID 不等于认证凭据。最多四个会话，十分钟未被接受使用则过期。
请求 ID 是 1…64 UTF-8 字节字符串或安全整数；拒绝批量请求、null/小数 ID、
重复 JSON 键和含 NUL 字符串。

HTTP/HTTPS MCP 共用一个 HID worker，单槽调度，忙碌时拒绝输入。启动默认 MCP，控制未授权；
物理启用才授予输入权限，不再选择控制来源，首个派发输入的会话拥有该权限；换会话需停止后
重新物理启用。权限不设时限，停止、USB掉线、切换模式、身份维护、显示故障或重启均撤销权限；
权限不持久化，重连不会恢复已撤销权限或重发动作。
每个输入最多八秒，同时检查取消、设备代际与授权。每会话保留 64 个输入 ID 哈希，
重复 ID 或记账已满均拒绝，不静默遗忘后重放；满后新建会话并重新物理启用。

长输入通过 IDF 异步请求响应，HTTP 任务可继续处理状态/停止/取消，HID 独立执行。
取消只匹配已认证的原会话和 JSON-RPC 请求 ID。独立按钮任务每 5ms 检查原始按键
以停止，菜单/启用决策另外去抖。USB 掉线、切换模式、显式停止及身份维护
会中断输入。拔线后释放为尽力而为；不撤销已发生效果。实际停止延迟待设备测量。
HTTP 响应断开本身不被视为必然取消：客户端应发送取消/停止，实体停止和单动作八秒时限仍生效。响应丢失属于结果未知，不表示可以安全重试。

`0.4.0-mcp` 删除旧 ANAN1 监听/解析/心跳和来源切换 UI。原生手机观察归客户端，
已检查的 Anan 观察就绪条件不要求旧输入连接。USB描述符及HID报告时序保留。
当前 `device_status.mode` 为 `mcp` 或 `setup`，没有旧 `usb` 控制模式。

两项服务要求本地 USB IP `192.168.7.1`、对端 `192.168.7.2`、准确 Host；若有 Origin，
必须同源。不开放 CORS。HTTP 提供配对/配置导出和已认证的 MCP 端点。请求体 4096 字节、JSON
嵌套最多 16 层、头部 2048 字节、收发等待两秒。这是有界本地服务，不是公网端点。
不主动记录请求、密钥或设备身份；SDK 诊断也不应作为公开原始日志提交。

## 黑屏启动排查

屏幕已显示状态后，直接点“设置”；长按黄键 A 0.7 秒仅为实体备用入口。正常应在启动时初始化显示，长按 A
不是点屏操作。烧录后短按电源键，退出下载模式/复位。
首个 MCP 候选收到用户黑屏反馈，根因和是否已复位尚未确认；下一候选补上 M5IOE1
唤醒/重试、事务处理间隔、关闭 I2C 休眠及 GPIO/供电回读。这是按源码修正启动流程，
还不代表设备已验证修好。

该候选可在直连手机打开 `http://192.168.7.1/status`，读取 `firmwareVersion`、
`displayStage`、`displayError`、`usbOnline`；设置页也显示这些信息。端点仅 USB、
不缓存、只读，不含设备身份或密钥，不能启用/发送输入。错误可定位到扩展芯片发现/
配置、显示供电、DMA 分配、SPI/面板初始化或像素传输。`ready` 只代表软件传输完成，
不代表实际观察到屏幕发光/像素。

`0.1.2-mcp` 修正 IDF IPv6 双栈监听下的 USB socket 地址检查：IPv4 映射 IPv6 地址
仍与原来的准确设备/手机 IPv4 地址对比较，原生 IPv6/其他对端仍拒绝。HTTP Host 和
Origin 接受等价的显式默认端口 `:80`，HTTPS 仍仅 `:8443`。拒绝响应现在指出地址/
Host/Origin 的具体类别，不回显请求值。用户反馈 `USB origin/host required` 后确认了
这处源码缺陷；手机是否恢复配置访问仍需重试验证。

## 触屏与双语操作

见[触屏 UI 决策及预定义检查](touch-ui.zh-CN.md)。主页显示 MCP控制、开始/停止和设置，
没有 Anan直连/来源选择；同一根 USB 线仍承载以太网和 HID。
备用操作：黄键选中/高亮当前按钮，蓝键执行，长按黄键进入设置；用于停止的按键会
消费至松开。触摸只有在同一已显示按钮上新点按/松开才执行，读取失败、移出按钮、
画面或控制状态变化都会取消本次点击。重置单独要求两秒按住。触摸 I2C 轮询和显示
任务与不使用 I2C 的高优先级实体停止任务分开。设备记忆所选语言，手机页面也有独立
双语开关。坐标映射、错误恢复、语言记忆和停止延迟仍需真机验收，编译/静态预览不
代表这些已经通过。

`device_status` 的 `controlEnabled` 仍为布尔值；启用时
`controlSecondsRemaining` 为 `null`（无时限），未启用为 `0`。
MCP 会话空闲过期与单动作八秒限制不变。
