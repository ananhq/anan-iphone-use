# 最小化板型适配

[English](porting.md) · 简体中文

通过 [anan-iphone-use](../.agents/skills/anan-iphone-use/SKILL.md) 引导用户确认硬件、最小适配、烧录与手机配置。**当前只有 M5Stack StopWatch 已实现。** 下文的其他板型与无屏流程是适配要求，不是已有支持。观察、模型和 Agent 留在客户端。

## 修改前确认硬件

收集准确板型/芯片/硬件版本、官方文档与原理图、原生 USB D+/D− 路径及接口、flash/PSRAM、启动/下载方式、电源线路/控制器、可用按键及有效电平、屏幕/触摸硬件或明确无屏，并确认手机与客户端。查询实际目标的官方芯片/开发板及 ESP-IDF 文档，记录已确认事实与未知项。USB-UART 或固定功能 USB Serial/JTAG 接口本身不等于可编程 USB Device HID/NCM。不能给其他板烧录 StopWatch 镜像。

芯片或线路不支持现有 USB Device 栈时，说明具体阻碍，建议合适的板型或另行商定硬件设计。不能把改引脚、编译成功当作已兼容。

读 `AGENTS.md`、[设计](design.zh-CN.md)、[来源声明](../THIRD_PARTY.zh-CN.md)与源码，检查已有改动。实施重大架构、电源、依赖或协议变更前，说明最小修改文件和实体交互方案。范围明确后实际完成适配与编译，不停留在通用计划。保留 StopWatch 目标与无关改动；必要时用小型明确的板型配置或独立 worktree，不顺便开发通用板级框架。

## 当前硬件耦合检查

| 范围 | 当前 StopWatch 假设 | 适配责任 |
| --- | --- | --- |
| `sdkconfig.defaults`、构建配置 | ESP32-S3、16MB flash 与当前内存设置 | 选择真实芯片及已核实的 flash/PSRAM；不支持的芯片不是换配置即可 |
| `partitions.csv`、`package.py`、`flash.sh` | 身份 NVS 位于 `0xf00000`；打包/烧录固定 S3/16MB 与合并镜像边界 | 分区适合实际 flash；同步调整该板打包、镜像边界、manifest 板型和烧录命令，普通升级不要擦除身份 |
| `main/hardware/board.c` | I2C SDA47/SCL48、M5PM1 `0x6e`、寄存器 `0x07` bit5、低电平停止 GPIO1/2 | 仅替换已确认的电源/按键；不在其他板发送 M5 电源写入，不开启会向手机反向供电的电源 |
| `main/hardware/display.c`、`main/hardware/touch.c` | CO5300 466×466 QSPI、M5IOE1 与 CST820B | 适配已确认的显示/触摸硬件，或实现下文经过讨论的无屏路径 |
| `main/app/device.c`、`main/ui/ui.c`、`main/ui/ui_layout.c` | 可见帧检查约束配对与控制开启 | 保留 StopWatch 检查；为无屏硬件提供独立实体授权路径 |
| `main/input/usb.c`、`main/input/actions.c`、`main/network/mcp.c` | USB NCM/HID、输入时序、七个 MCP 工具及会话 | 尽量原样复用；保留释放/停止、不重放和全新显式授权 |

保持工具/会话行为、HID 描述符、USB 标识、手机子网检查稳定。不恢复旧 ANAN1/TCP28766，不顺便加入 Wi-Fi/BLE、截图或 [Anan](https://anan.sh) 代码。加入第三方代码前记录准确版本、复用文件、修改及许可。

## 没有屏幕的设备

当前 `main/app/device.c` 依赖 `screen_ok` 和当前已渲染帧才能确认配对、开启控制。只删除显示初始化不能让无屏板可用。直接设置 `screen_ok = true`、自动确认配对、启动/重连即开启控制，都是绕过现有交互，不是适配。

先根据实际板型商定简单实体流程。优先考虑可用的 **USER 按钮与 LED**，配置与 JSON 留在现有手机网页。单按钮可按状态区分进入配置、确认待配对、独立开启控制的手势；编码前明确时长与反馈。不能默认 BOOT/RESET 可复用，需检查绑带引脚、复位线路和启动行为。

方案必须涵盖：

- **主动进入配置：** 通过实体操作开启有限时长的配置窗口，不永久开放配对。
- **主动确认配对：** 全新实体手势绑定当前待配对。无屏时不能进行 StopWatch 的六位数字目视比对；选择并解释真实替代方式，例如 LED 验证码反馈或明确商定的实体确认流程。不能声称核对了只在手机显示的数字。尽量保留配对/配置 API 和 Bearer 行为，必要契约变化先讨论。
- **单独开启：** 导入 JSON 或配对完成不授予输入；配置结束后需要全新实体操作和可理解的状态反馈，授权不持久化、不自动恢复。
- **立即停止：** 控制/输入期间指定停止键优先停止，消耗该次手势直至松开，不能同时重启控制或重置。此路径不依赖显示、I2C 或网页，保留 MCP `stop` 与 USB 拔线撤权。
- **状态与恢复：** 用实际 LED/手机反馈区分配置、就绪、控制、错误；重置配对是单独的有意操作，按适用范围保留语言/身份存储规则。没有可用实体输入时，提出外接按钮或另行讨论交互，不能悄悄删除授权。

以小范围板型分支实现无屏授权，复用已有配对、授权、取消与停止原语。保留 StopWatch 显示故障时禁止控制的行为；不能把坏屏 StopWatch 自动当无屏设备。实现板型后同步更新中英说明中的真实手势与反馈，不对无屏用户套用 StopWatch 触屏步骤。

## 构建、烧录与完成配置

编码前定义该板验收场景：电源与 USB 枚举、配置/确认、独立开启、实体/MCP/拔线停止、无自动重放或授权恢复。按真实目标构建/打包，核对偏移和 flash 容量，记录源码/镜像 hash 与工具版本。静态成功不证明 USB 枚举、按键时延或手机输入。

使用用户当前串口和该板镜像给出命令。Agent 执行烧录、硬件探测/输入、E2E 需当前目标/范围授权，当前明确烧录请求可提供该授权。不对其他芯片/分区直接使用 StopWatch `flash.sh`，不默认整片擦除或改 eFuse。

写入验证后，按 skill 完成手机流程：连接 iPhone ↔ 原生 USB，USB 以太网 `192.168.7.2/24`、无网关/DNS，开启辅助触控，安装/打开手机客户端，通过 `http://192.168.7.1` 实体确认配对，复制/导入 MCP JSON，再用该板真实控制方式开启。HTTP 不需要证书。客户端负责观察与任务授权；电脑支持 MCP 不代表能访问手机 USB 子网。
