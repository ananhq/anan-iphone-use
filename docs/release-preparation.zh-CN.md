# 开源发布准备

[English](release-preparation.md) · 简体中文

Anan iPhone Use（`anan-iphone-use`）：本文件记录本地整理状态，不代表已经公开发布或完成来源审计。
仓库包含固件、固定构建输入、双语文档和脱敏迁移证据。
公开项目地址尚未确定，现有许可证声明保留。

## 本地基线顺序

1. 整理文档，检查源码等价、链接、产物忽略及独立编译/打包输入。
2. 将有明确标识的候选镜像交给用户重新烧录，按[手动验收步骤](baseline-acceptance.zh-CN.md)验证。
3. 用户反馈重新烧录成功后，已授权首次本地检查点；输入/停止验收与来源缺口保持待处理，完整基线范围与来源处理另行确认。
4. 在该检查点之后，继续单独约定的无线/MCP 研究与实现，保留当前 USB 方案。

## 二进制发行的额外要求

- 检查实际链接的应用和引导程序组件，包含适用的 SDK、库和 ROM/专有声明。
  现有许可副本不是完整的二进制许可清单。
- 从有明确标识的源码 commit 和固定工具链构建，记录镜像/源码/锁哈希、偏移、Flash
  大小和具体验证范围。本基线保留历史 IDF 应用版本 `ec6bb29-dirty`，发行版本调整另行决定。
- 随发行提供适用声明及配置/恢复说明，不包含原始本机日志、私人配置或设备标识。
- GPL-3.0-only 二进制发行时，按 GPLv3 提供对应源码及所需构建/安装材料，保留依赖与修改声明，见[许可与来源处理](license-plan.zh-CN.md)。
- 确认实际验证镜像就是要发行的镜像。重新构建后比较哈希，编译成功不继承设备验收。

生成文件保留在被忽略的 `build/` 和 `managed_components/`。
`artifacts/migration/` 是历史证据，保持原样；新增基线证据放在 `artifacts/baseline/`。
证据边界见[验证记录](validation.zh-CN.md)。
