# 无线开发与验收

[English](wireless-development.md) · 简体中文

已同意范围：保留现有 USB NCM/HID，为 M5Stack StopWatch 增加局域网 Wi-Fi
HTTP MCP 和实验性 BLE HID 后端。客户端仍负责观察。不修改客户端、不增加
AirPlay 接收器、云中转、输入自动重放、恢复控制授权或新的公开 MCP 工具。

实施前确定验收场景：

- 离线：保留 USB 描述符与发送函数体（只重命名后端符号）、现有动作时序和七个
  工具 schema；模拟 USB/BLE 状态，检查显式选择且无自动回退。
- 离线：检查 BLE 报告长度、引用、坐标端点与绝对定位/相对按键分开发送；只向
  加密且订阅报告的连接发送，完成等待有界，不重试报告。
- 静态/编译：使用锁定 IDF；审查同源和接口校验、首次仅 USB 配网、LAN MCP
  token 校验、配置持久化、StopWatch 控件及中英文字符/布局覆盖。
- 另行授权实机：USB 点击/拖动/输入/停止回归；BLE 配对、键盘、绝对定位加相对
  点击、按住拖动、滚动、Consumer 键及停止/断连；然后测试 Wi-Fi MCP＋USB/BLE。
- 另行授权集成：同一 iPhone 的 Anan 使用 Wi-Fi MCP＋BLE HID；电脑 MCP 客户端
  自行提供观察。检查会话竞争、回复丢失、拖动中网络/蓝牙断连、射频共存与续航。

编译和离线模拟不证明 iPhone 兼容、通知交付、端到端停止延迟、射频表现或续航。
BLE 绝对定位是首个实机验证点。执行需当前设备和范围的明确授权。

首版通过现有 USB 配置网页保存一个 2.4 GHz Wi-Fi 网络，设备作为 station 加入，
屏幕显示 IPv4 地址。临时配网热点和 mDNS 暂缓。LAN HTTP 导出凭据与现有 USB
Bearer 配置同样敏感，使用可信局域网。HTTPS 保持仅 USB，因为现有证书只覆盖
USB 地址。输入通道显式选择、默认 USB，与 MCP 网络接入独立；切换和重连不
开启控制。

实现参考已锁定 ESP-IDF v5.5.5 NimBLE API 和 TinyUSB 描述符宏，不复制厂商
demo 或其他应用实现。BLE 绝对定位后发送相对鼠标按键是参考 xhoantran/iphone-use
思路的实验性设计；USB 描述符保持不变。

## 扫描选择配网阶段

实施前确定验收：已配对的 USB 配置页启动单个有界异步 station 扫描并轮询；
配置和扫描不并发。未配网设备可扫描，不尝试用空凭据连接。扫描暂停连接重试，
完成/失败后恢复保存网络，不恢复控制。结果有界、去重，排除隐藏/非法 UTF-8
名称，不返回 BSSID 或密码。网页以纯文本/value 赋值，保留手动名称，换网时清空
密码。选择开放网络清空并禁用密码，手动编辑后恢复。实施前网页验收只使用合成
响应；实际射频扫描、BLE 共存、超时恢复与手机配置仍需真机验证。不增加依赖或
MCP 工具/schema，不读取系统 Wi-Fi 密码。
